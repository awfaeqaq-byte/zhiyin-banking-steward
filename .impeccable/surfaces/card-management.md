# 银行卡管理 · 2026-10-21

## 范围与布局

沿用首页浅蓝白画布、墨蓝文字、青绿操作色和细边框；不新增全局 token。入口为底栏「卡片」或「我的 → 银行卡与安全」。标题旁保留返回和刷新；返回沿原来源路径恢复页面。

手机以钱包层叠三张银行卡，主卡、生活卡、储蓄卡分别采用深青、浅鼠尾草、墨蓝材质；两个未选卡露出可点击卡口（54px），选中卡完整展开放到前景，显示名称、尾号、状态和后端账户余额，并以勾选及 `aria-pressed` 标识。默认展示主卡，指定卡入口直接展开目标卡；DOM 与视觉顺序一致，点击换卡后焦点保持在同一卡，程序入口不抢焦点。下方大白详情卡收紧为可用余额小行与转账入口；桌面详情分两列，手机按「余额与操作 → 权限安全 → 流水 → 新卡申请」排列。

当前卡详情紧接选择区。权限说明随开关表达实际结果，例如「已关闭 · 拦截境外渠道付款」，不以静态“允许”文案描述关闭状态。流水默认收起，展开后只呈现本卡记录；新卡申请与已登记卡管理分开，放在主卡的独立折叠入口。

## 操作、确认与恢复

详情按卡 ID 重挂载，余额、权限、错误和未确认弹窗不随切卡串用。已验证快照按卡保留，切回时继续显示该卡已有内容，首次读取预留详情高度；主卡管家入口移至权限区末尾，避免不同卡片的权限标题跳位。缓存仅用于展示，重新读取的实时版本达到缓存版本后才开放操作；旧版本响应保留缓存并提供重试，不倒退显示或使用旧版本提交。挂失、恢复、限额和权限修改均先展示卡名与尾号，再由本人确认；等待确认期间账户版本改变，则旧确认失效并要求重新核对。请求失败保留错误及重新读取入口，不能用零余额或空流水冒充成功读取。只有服务端保存成功才显示对应尾号的回执。

「用此卡转账与 AA 收款」携带选中卡 ID；方案、付款、预约、AA 和回执均使用该卡账本。转账与 AA 的待核实恢复标识按卡隔离，重新打开时核对同一卡原请求，不把另一张卡的 pending 状态带入，也不据此自动重新付款。

返回按钮（44×44px）、其他动作和展开入口至少（44px）；开关轨道保持紧凑，点击区域外扩至至少（44px）。确认使用现有 Radix Dialog 的焦点与关闭机制；错误用 `alert`，成功回执用 `status`。卡面始终保持（214px）完整尺寸；外层仅把露出的（54px）卡口作为未选卡触控区域，内层完整卡面不接收点击。换卡通过 WAAPI 从点击当刻的实际位置平移（280ms），新前景以（220ms）淡入，取消高度伸缩与缩放。连续切换先记录当前帧，再取消旧动画并接续；减少动态效果、页面隐藏或卸载时取消运动。展开箭头保持（180ms），刷新只在真实请求中旋转。

## 跨页衔接

资产总览在原主账户资产汇总上，只加其他银行卡现金，避免重复计算主卡现金；「其他银行卡」显示副卡合计并直达生活卡。返回可恢复资产页。日程中的预约带卡 ID、卡名和尾号，查看、修改或撤销回到原卡流程，不默认切换成主卡。

## 已实现边界

这三张卡是本地银行账本中的固定登记卡：日常支付卡（primary，8888）保留原余额和历史；生活备用卡（living，6216）、储蓄备用卡（reserve，9073）以零余额初始化。页面所有金额来自账本，不为呈现多卡而编造资金。固定登记不等于完成真实银行绑定或开卡。

新卡申请目前只保存 `submitted` 状态，不自动发卡、不自动增加第四张银行卡。管家未指定卡时仍默认主卡；卡片页的「让管家帮我核对这张卡」仅主卡提供。明确副卡的设置意图可定位本卡，再由用户核对操作。副卡尚未接入财富申购、定期存款和生活筹备，不应暗示这些功能已支持任意银行卡。

# 首页对话任务卡片 · 局部表面记录

## 范围与方向

依据团队的智能转账、订阅管理、跨场景联动方案，把已有业务数据和操作入口整理为三类稳定的对话组件。继承 `docs/home-ui-preview/DESIGN.md` 的浅蓝白画布、墨蓝正文、青绿操作和动态管家身份。2026-10-16 经用户授权，首页配色成为根 `DESIGN.md` 与其他业务页的共同基准；本记录说明对话任务卡的具体实现，业务计算与授权边界保持不变。

`index.html` 的 TASK REPLIES 契约：转账核对、平台签约订阅和关联场景回执使用固定结构，数字与阶段来自数据，不用装饰性成功状态代替结果。

## 层级与样式

外层仍由管家消息气泡提供白底、细边框、`2px 14px 14px 14px` 圆角和 `13px 14px` 内距；任务组件不再套一层带阴影的卡片。管家名字与 AI 标识位于业务内容之前，真人肖像复用已有宁宁／阿衡素材。

内部按“标题与任务阶段 → 来源与范围 → 业务事实 → 异常说明 → 当前可做的操作”阅读。正文、辅助文字、图标与操作、强调状态面和分隔线分别使用 `--ink`（`#133346`）、`--muted`（`#506d7c`）、`--teal`（`#007d7c`）、`--pale`（`#eaf8f7`）、`--line`（`#d5ebee`）；错误文字使用 `--danger`，缺省为 `#983c35`。按钮沿用已有 `Button` 的 primary、secondary、ghost 状态。聊天通用按钮样式排除 `.button-base` 与 `.switch-root`，由共享控件保持各自的外观与操作层级。

组件采用网格布局，主间距 `14px`；共享任务标题为 `16px / 1.45`，正文说明为 `14px / 1.7`，元信息与细注为 `12px / 1.65`，阶段标签为 `12px / 1.5`。账单分节标题为 `15px`。转账收款人 `20px`，金额 `clamp(22px,6vw,28px)`；月度合计 `24px`。金额使用等宽数字，不以大字号覆盖必要的来源和执行条件。字体继承系统中文无衬线栈。

事实表为两列，正文 `14px`，标签与右对齐数值之间留 `8px`，上下内距 `12px`。订阅逐项用细线分隔；行操作可换行，长名称和数字允许断行。主按钮宽度 `100%`、最小高度 `44px`、圆角 `10px`；次级取消按钮使用 `12px` 灰蓝文字，最小宽高 `44px`。小于 `360px` 时转账对象、金额与订阅合计可换行，事实表标签列缩至 `80px`。长回复继续由现有中部会话滚动，输入区保持原有固定位置。

`TaskCardHeader` 从 `task-card-header.tsx` 导出并自行加载样式，接收 `title`、`icon`、`status`、可选 `tone` 和 `meta`。标题为 `h2`，图标为装饰信息；标题与阶段行允许换行，元信息置于下一行。`tone` 支持 neutral、attention、success、warning、danger，以文字说明阶段，不靠颜色判断结果。neutral 使用浅蓝底与灰蓝字，attention／success 使用浅青绿底与青绿字，warning／danger 使用对应语义色。

右侧标签只表达阶段。“平台签约”属于订阅来源，放在 `meta`；账单的“只读分析”与来源也放在 `meta`。订阅阶段为“待你核对”“待重新核对”或“暂无签约记录”。账单阶段分别表达正在核对、核对失败、等待补充、等待授权、暂无记录、待补全记录和分析已就绪，空数据或未授权不能显示为完成分析。共享头也用于账单授权与工作区，以及 AA、生日筹备和点餐现场，各自根据实际业务状态提供阶段文字。

## 组件与行为

| 组件 | 固定信息 | 操作与边界 |
| --- | --- | --- |
| `TransferPlanCard` | 收款人、账号尾号、金额、执行时间、银行沙箱来源；有有效快照时展示保留金额、其他预约、测算剩余可安排 | “核对银行转账／核对预约转账”只调用既有核对入口。明确说明“尚未转账，打开核对不会扣款”。卡片挂失、方案无效或可安排金额不足时禁用入口。没有余额快照时不补造余额，说明核对页会重新检查。 |
| `SubscriptionReviewCard` | 标题下显示“来源：已授权平台签约”；仅汇总月周期项目，逐项保留金额及周期，最多展示前四项 | 提醒使用已有 Radix `Switch`，相邻文字显示“续费提醒”与“已开启／已关闭”，仅修改该项提醒偏好；灰蓝次级“核对并取消…”进入取消核对，“查看自动续费清单”打开完整清单。年度费用不混入月合计。读取失败时隐藏金额与逐项操作；空签约数据说明规律付款仍需核对，不能断言没有订阅。 |
| `SceneProgressCard` | 场景标题、当前阶段、摘要、最多五条业务记录、核对时间 | 排除普通消息记录；超过五条说明完整记录数量。按 `scene.next` 显示原订单、筹备、收款、日历或银行记录入口；没有下一步则不显示按钮。恢复期间禁用按钮并显示“正在打开…”，失败用文字告警。此处查看进度，付款与预算仍单独确认。 |

跨场景阶段来自 `SceneFlow`：正在整理、需要你补充、等待你确认、等待平台结果、已完成、已取消、待处理。业务记录各自展示真实状态，未知值显示“状态待核对”；商家已接单不等于已送达，方案待核对不等于预算已预留。

## 数据、触发与保留金额保护

真实会话由 `steward-chat-home.tsx` 在连续对话模式、管家消息且未打开历史时选择组件。`prepare_transfer` 且有核对回调时呈现转账卡；`open_subscriptions`、`prepare_cancel` 或明确的订阅概览问句呈现订阅卡；最新关联场景消息呈现进度卡。选择顺序为转账、订阅、场景，其余解释沿用普通回复。每个事项只保留最新回复的动作入口；场景只给最新回执恢复入口。

转账参数来自结构化 action，收款对象来自既有名单，快照来自有效银行沙箱状态及 `transferImpact`。订阅来自已有授权连接的签约数据与提醒偏好，场景来自已有 `SceneFlow`。组件不新增读取授权、扣款、取消签约或预算执行能力。

后台分流通过 `steward-workspaces.tsx` 把 `activeRun.prompt` 原始整句传入 `sourceText`，生成转账回复时保存为 `transferSource`。卡片检查原句中的保留约束：若方案缺失保留金额，或可识别的金额与方案不一致，显示“约束待核对”，将保留金额写为“尚未核对”、剩余写为“待补全方案后测算”，并禁用核对入口；不得显示为零或宣称已计入。

这一检查保护已识别的保留表达，不代表多子句任务已能完整、确定地解析和路由。底层仍可能把复合请求拆开而遗漏上下文；当前让遗漏方案停止进入核对，并请用户重新说明转账金额与需保留金额。

## 可访问性与扩展约束

三类组件使用有中文名称的 `section`；事实使用 `dl`，项目使用 `ul`／`ol`。装饰图标 `aria-hidden`。提醒控件的角色为 `switch`，可访问名称为“{服务名称}续费提醒”，由 `aria-checked` 表达开关状态，支持键盘切换；禁用时不修改偏好。开关最小宽度 `44px`，既有伪元素将轨道上下命中范围扩展至 `44px`，不把外观拉成整行按钮。错误采用 `role="alert"`，对话继承现有 `aria-live="polite"`。任务按钮与开关焦点为 `2px solid var(--teal)`、外偏移 `3px`。沿用首页减少动态效果设置，任务卡本身不增加动画。

后续扩展继续用类型化数据、可追溯状态和已有核对回调，先展示关键事实，再给一个明确的下一步。未知金额、状态和授权范围必须写明待核对；不同收费周期分开表达；错误、等待、禁用和恢复路径与正常状态一起维护。不要把卡片入口写成已执行结果，也不要用任意模型文案推断成功。

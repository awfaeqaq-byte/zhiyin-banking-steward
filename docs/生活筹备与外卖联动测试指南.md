# 生活筹备与外卖联动测试指南

本指南依据当前生活筹备、银行预留、手机外卖桥接及支付代码。演示覆盖沙箱内的持久银行状态、真实应用桥接和账单记录；没有真实银行扣款、商家履约或线下配送。

## 测试入口

从项目根目录启动手机沙箱：

```sh
npm run phone:dev
```

打开 `http://localhost:3000`，进入知银。“我的 → 生活筹备”可以新建安排；在首页提出生日筹备请求后，点击“核对生活筹备”也可以进入。同一安排在任务日历、首页到期提示和生活筹备中复用。

手工填写对象、预算、开始筹备、希望送达、地址和联系方式后即可保存，不必依赖模型。自然语言整理需要本地已配置的模型服务；不要把供应商密钥或模型原文附到测试报告中。

独立知银页面可以查看／编辑方案，但外卖联动必须从手机沙箱打开。独立页点击外卖入口应得到“请从手机沙箱打开知银”的说明。

## 一条完整验收路径

1. 新建安排，填写未来送达日期、开始筹备日期、收货资料，设置预算（例如1,000元），选轻甜鲜果蛋糕与粉玫瑰。自然语言建议只填方案；继续核对和手工调整。
2. 保存后检查“尚未预留资金”。筹备详情默认折叠，可展开编辑；商品默认只显示已选项，“调整商品”可以重新打开目录。
3. 点击“预留这笔预算”。此时应只出现确认说明；点击“确认预留”后才显示“预算已预留”。银行卡总余额不减少，可用资金扣除预留；其他银行卡消费、即时转账和预约不能使用受保护预算。
4. 在蛋糕行点击“准备订单并去外卖”。收银台应保留该商品、地址、联系方式、送达时间与备注。蛋糕（198元）加配送（8元），单笔应为206元。两个商品组合报价为382元，分别准备各自订单。
5. 核对付款渠道和资金来源。微信支付／支付宝可选择；筹备订单固定使用常用卡8888的预留预算。按钮同时显示渠道、常用卡和金额，不把平台钱包余额作为本次预算。
6. 明确付款后，订单进入追踪页；银行卡余额减少206元，所选支付应用写入对应账单。返回知银，点击“核对订单状态”，实际支出增加206元、仍在预留变为794元。再次打开同一订单应复用原编号，避免重复扣款。
7. 在外卖订单申请退款。成功后应明确显示原路退回常用卡8888，银行卡余额恢复。安排仍为“筹备中”时，实际支出回到0元、仍在预留回到1,000元；返回知银后刷新或核对订单状态可看到“已退款”。该已退款订单不能重新付款。
8. 在知银点击“取消安排”，阅读说明再确认。未用预算释放，原订单入口保留。已付款订单不会因此自动退款；已取消安排的未付款订单不能继续使用原预留预算。

另建未退款的安排可验证完成路径：为每个已选商品准备并支付订单，在订单追踪页使用“模拟下一阶段”推进到已送达，返回知银核对全部订单状态后，“确认已收到，完成安排”才可用；再次确认完成释放剩余预算。配送推进是沙箱模拟。

## 资金状态口径

| 项目或动作 | 当前含义 |
| --- | --- |
| 商品与配送合计 | 当前已选商品目录价与各自配送费之和。 |
| 预算 | 用户核对保存的本次上限。 |
| 实际支出 | 本次安排已付款且尚未退款的金额。 |
| 仍在预留 | 筹备中安排的预算减实际支出；取消或完成后为0。 |
| 常用卡可用 | 银行卡余额减去所有仍在预留的筹备预算。 |
| 退款 | 原路回卡；仅仍在筹备中的安排重新保护退回金额。 |
| 取消 | 释放未用预算，不退已付订单。 |

银行状态保存在服务端文件中，刷新或重新打开知银仍能读取。外卖订单与微信／支付宝账单属于当前浏览器的沙箱应用状态；跨浏览器只读到银行安排不等于拿到了原外卖订单，不应为排错清空用户数据。

## 异常与边界验收

- 缺少必填资料、商品超过预算、无效商品、重复商品或不合理预算时，保存应拒绝并提示核对。
- 日期按北京时间输入／显示。送达须在未来一年内，开始筹备不能晚于送达。模型日期建议由程序转换，并拒绝过去送达、无效日历日期、倒序和超过范围的日期。两个时间分别表示开始筹备与希望送达。
- 未预留或未保存修改时不能准备订单。已有订单后不能悄悄改金额、商品或收货资料；先处理原订单，再重新安排。
- 预留时会核对现有预约、其他筹备预算与账户版本。卡挂失、夜间保护、限额、资金不足或账户状态变化时应看到错误，不能显示成功回执或自动换资金来源。
- 网络或桥接失败时保留输入和原订单身份，按错误提示刷新／重试；核对成功之前不声称已付款、已退款或已配送。
- 日历记录开始筹备与期望送达两个事件。首页到期提示只针对已预留安排，并返回同一方案；提示取决于应用运行和当前可见状态，不提供离线后台提醒、后台下单或自动购买。
- 希望送达时间不是商家承诺，订单中的骑手、进度与送达为沙箱模拟。
- 手机检查16px输入、44px以上按钮、折叠详情、资金标签和错误可读；键盘检查焦点、表单标签、复选框、展开入口与按钮；减少动态效果偏好关闭加载旋转。

## 隔离冒烟脚本

手机开发服务运行后，在项目根目录执行：

```sh
node scripts/occasion-smoke.mjs
```

脚本使用临时银行文件和新浏览器上下文，不修改用户银行／钱包记录；结束时关闭浏览器并清理临时银行文件。模型建议使用固定桩，银行 middleware、手机桥接、商家订单与平台 ledger 使用实际代码。它验证方案保存、独立预留确认、微信渠道／银行卡付款、账单、退款、取消，以及手机／桌面无水平溢出，并将五张截图写入 `.impeccable/review/`。

默认服务地址为 `http://localhost:3000`；可用 `PHONE_URL` 指向已运行的手机开发服务。默认使用 macOS Chrome，可用 `CHROME_PATH` 指定本机浏览器可执行文件。脚本不验证在线模型的回答质量、支付宝交互分支或真实配送；金额保护、字段／日期校验等由单元与组件测试补充。

相关定向测试：

```sh
npm test -- src/lib/occasion-plans.test.ts src/lib/occasion-food.test.ts src/components/occasion-planner.test.tsx
```

根项目全量回归与构建沿用项目命令：

```sh
npm test
npm run build
npm run phone:build
```

MobileGym支付／订单定向测试从 `mobilegym` 目录执行：

```sh
npx vitest run tests/foodDeliveryBank.test.ts tests/foodDeliveryPaymentBackend.test.ts tests/foodDeliveryPaymentUi.test.ts tests/foodDeliveryOrderFlow.test.ts
```

新模块定向覆盖率从项目根目录执行：

```sh
npx vitest run src/lib/occasion-plans.test.ts src/components/occasion-planner.test.tsx --coverage --coverage.include=src/lib/occasion-plans.ts --coverage.include=src/components/occasion-planner.tsx
```

代码定位：`src/components/occasion-planner.tsx`（方案与确认）、`src/lib/occasion-plans.ts`（报价、日期与金额口径）、`server/bank-store.ts`（持久预算与付款）、`src/lib/occasion-food-bridge.ts` 和 `mobilegym/apps/Zhiyin/occasion-food-access.ts`（手机桥接）、`mobilegym/apps/FoodDelivery/pages/PaymentPage.tsx` 与 `OrderTrackingPage.tsx`（外卖付款和退款）。

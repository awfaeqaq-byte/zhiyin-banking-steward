# 基础功能核查与复杂场景验收（2026-10-09）

本次核查以本地比赛沙箱为范围。所有资金、卡片和申请操作仅改变本机沙箱状态，不连接真实银行。

| 场景 | 当前实现 | 关键边界 |
| --- | --- | --- |
| 消费分类统计 | 授权交易按月重新计算支出、普通入账、退款、转入／转出；分类金额与占比可查看明细 | 同平台交易 ID 去重，跨平台同额保留；缺少记录不等于零消费 |
| 异常交易识别 | 较大金额、同日高频、周期规律作为待核对线索，能查看交易证据并在自动任务中确认或排除 | 规则线索不等于欺诈判定；目前没有设备、地域或商户风险数据 |
| 月度／年度报告 | “我的账单”按授权数据生成月报、年报和按月趋势；月报可下钻纳入统计的交易 | 年报只汇总有记录月份；授权来源不完整时金额是已返回记录小计 |
| 产品推荐与对比 | 风险、投入金额、期限确定性筛选；展示风险、费用、最低持有、赎回规则和产品数据日期 | 三个产品为演示目录，未接正式产品文件与实时在售系统 |

| 申购／赎回 | 独立确认、服务端重验、幂等回执、银行统一余额扣加、持仓更新、封闭期拦截 | 银行与理财共用同一持久化文件及锁；演示价值按本金展示，不模拟市场净值或真实到账清算 |

| 额度调整、交易限制／解锁、挂失 | 自然语言可预填核对页；设置经版本校验保存；挂失、单笔限额、夜间保护、无卡支付可拦截相应沙箱付款；境外开关连接可验证的 ¥1 沙箱付款渠道 | “额度”指单笔支付限额，不是信用额度；境外渠道仅为人民币演示，不含真实跨境清算或汇率 |

## 新增复杂测试场景

- 账单：跨平台同额、同平台重复 ID、退款、转账、跨月、无授权、不完整来源、年度与各月金额守恒，以及页面交易下钻。
- 理财：测评缺失或降级、超风险产品、余额不足、取消确认、费用扣款、重复确认、持仓复查、封闭期拒绝赎回、赎回到账与重复提交。
- 卡片：自然语言调额只预填、取消不变更；申请取消、重复编号、旧版本拒绝；挂失、超限和无卡支付限制对付款的实际拦截。
- 统一资金：理财方案生成后银行付款使旧方案失效；确认申购即时减少银行卡余额、重复确认不重复扣款、赎回恢复余额；旧理财文件只迁移一次。
- 后台月报：读取真实格式 XLSX、核对文件哈希和上月口径；两次运行之间来源变化会反映到新报告，撤销授权后记录失败，不复用浏览器旧摘要。
- 境外渠道：关闭开关拒绝付款且余额不变，开启后回执与余额同步，挂失后继续拒绝。

旧版“风险评级有变化”的固定仓位与余额已从入口移除，资产健康入口现进入实际风险测评。旧理财文件首次接入统一资金账本时会并入持仓，并根据旧理财剩余资金计算历史净投入；待确认方案会失效，避免沿用旧余额。若银行余额不足以承接历史净投入，服务会停止迁移并提示人工核对。

## 后续仍需改进

1. 定时月报已在服务端执行时重新读取已授权的本地微信 XLSX，按北京时间生成上月报告，并记录读取时间、月份和失败原因。支付宝及非本地微信来源仍缺少可脱离浏览器运行的服务端适配器；这类来源会明确失败，不会冒用旧快照。配置文件、原账单或授权缺失时亦不会生成报告。电脑休眠或本机服务停止时仍不能执行。
2. 本机微信导入中存在隔离行时，报告将标注“已返回记录小计”；若要证明全月完整覆盖，需要来源提供可核对的总笔数与按月隔离明细。
3. 统一账本是本机沙箱实现；真实金融系统还需要交易数据库、审计、并发和崩溃恢复验证。真实卡申请仍需要身份核验、审批状态和通知通道。
4. 交易线索目前是规则识别，缺少标注样本和误报率评估；不应宣传为欺诈检测系统。

# 银行卡与即时转账

## 测试入口

- 资产 → 我的银行卡 → 管理 → 即时转账；不依赖模型即可操作。
- AI 原生首页告诉宁宁“现在给妈妈转2000元”，模型准备动作后点击“核对银行转账”。核对页可修改收款人和金额，最后明确确认才执行。
- 账单在银行卡页面。即时转账会扣减后端余额、增加收款方沙箱分户余额并生成回执，资产总额同步变化。
- 初始活期资金42,300元，初始单笔限额20,000元，可设置100—50,000元；挂失和夜间保护（北京时间23:00—06:00）由后端执行校验。

## 当前边界

只支持常用卡8888向已登记的妈妈6621、爸爸7316即时转账。收款人是沙箱分户账，不是微信好友零钱，也不会改动微信或支付宝余额。境外、无卡支付开关持久化，但对应交易渠道尚未实现。旧经典款预约演示保留，明确标注为模拟，不会执行扣款；新即时转账不支持预约、还款预留或跨平台归集。总资产中的理财与定存仍为演示持有数据。

银行账单询问可提供当前银行状态及最近3笔转账，不将它们冒充完整月度消费分析。银行卡页可查看全部沙箱转账。模型只生成准备动作；用户输入确认不等于付款授权，必须点击核对页的确认按钮。

## 接口

`GET /api/zhiyin/bank` 返回余额、限额、卡状态、控制开关和转账账单，金额单位为分。

POST 请求要求同源、JSON、`X-Zhiyin-Bank: 1`，支持：

- `prepare`: recipientId、amount。创建5分钟有效且绑定账户revision的方案，不扣款。
- `confirm`: draftId、authorized:true。只能提交已核对方案，不接受修改金额或收款人；同一draftId幂等返回原回执。
- `status`: draftId。查询方案或已完成回执，供未知结果恢复。
- `settings`: revision以及limit/frozen/controls。乐观锁防止旧设置覆盖新状态。

`.zhiyin-bank.local.json` 保存在项目根目录；排他锁和原子重命名把付款、收款分户、回执一起写入。已完成回执不自动删除，最多5000笔后拒绝新交易。文件损坏停止操作，不自动重置。静态文件访问被拦截；不要打包私人账本或上传Git。

## 安全范围

这是单用户、本地演示沙箱，不是真实银行支付系统：没有账号隔离、银行认证、支付密码或生物识别签名。`authorized:true`表示前端明确确认，不是安全支付凭证。不要暴露到公网。刷新后的未知交易先查询原方案，不能直接创建新付款。

后端和HTTP测试使用临时账本，前端测试使用受控回复，不改动实际沙箱资金。夜间保护用服务器现实时间，不使用手机模拟时间。

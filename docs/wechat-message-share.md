# 微信所选消息分享给知银

第一版支持 MobileGym 微信单聊和群聊的文字消息。用户主动提供材料，知银在首页同一段对话中理解、追问并接入已有事项流程。

## 测试路径

1. 刷新整个手机沙箱，打开微信聊天。长按文字消息进入选择；电脑可右键，键盘可聚焦消息后按 Enter。点选其他文字消息可多选，再点一次取消选择。
2. 点击「分享给知银」，核对原文、发送人、时间、聊天名称。最多5条、合计1000字；超长会提示，不静默截断。附言最多200字，例如「先解释一下」或「帮我准备生日，预算500元」。
3. 点击「分享并打开知银」。首页先展示材料；可移除、补充要求或点击「交给当前管家整理」。接收时不调用模型，也不创建业务事项、订单或资金操作。
4. 只解释消息时，不因原文包含生日、AA或转账关键词就准备操作；未填写附言时先整理需求和建议。明确要求筹备、点餐或转账时，进入对应事项的现有核对流程；明确关联已有事项可续接，有歧义由管家追问。
5. 原文随事项对话保存，首页以可展开的微信引用呈现。相对日期提供每条消息的北京时间作为依据；日期解读准确性仍需用实际模型逐场景测试。

分享不等于金融或平台授权。预算预留、订单生成、付款、群收款等沿用现有独立确认流程；只选择消息不会授权群成员资料或整个聊天历史。图片、语音、文件及支付卡片不在本版分享范围。

## 恢复和边界

- 微信选择和预览使用 URL 状态，返回先收起键盘，再关闭预览、返回选择。提交失败保留预览供重试。
- 只传所选文字、发送人名称、消息时间及当前聊天的标识与名称，不传未选消息、整个联系人列表或群成员档案。
- 分享经 OS 的显式文本 Intent 进入知银，只接受微信调用来源；WebView 桥检查同源、父子窗口和协议。
- 本浏览器的待处理材料持久化在 `zhiyin-wechat-share-inbox`。最多10份待处理材料，保存最近100个分享编号以去重；完成或移除后，重新打开知银不重放。存储失败不确认已接收。
- 分享原文只作为引用材料，不具备执行权限。模型只读解释返回的操作标记会被丢弃。确认金额、对象、时间和付款渠道仍由已有业务模型及服务端校验。
- 这是沙箱微信入口，没有接入真实微信分享扩展。

## 复验

```sh
npm test
npm --prefix mobilegym test
npm run build
node scripts/wechat-share-smoke.mjs
```

冒烟脚本默认访问 `127.0.0.1:3000`，可通过 `PHONE_URL` 指定其他已启动的手机服务。脚本使用新浏览器、内存事项及临时银行文件，模型以固定桩替代，验证长按多选、预览、返回、未选消息排除、只读解释、刷新去重、群消息续聊及明确生日筹备；不修改用户资金、聊天或本地业务文件。截图写入 `.impeccable/review/wechat-share/`。

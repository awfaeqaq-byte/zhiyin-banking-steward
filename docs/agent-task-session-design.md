# 宁宁 Agent、任务规划、会话与可视化设计

> 适用场景：账单分析、理财操作、卡片管理  
> 版本：MVP v1.1，2026-10-01  
> 原则：模型负责理解、规划和解释；确定性代码负责计算、约束、执行和回执。

## 1. 产品判断：需要 Agent，但不是三个自由发挥的聊天机器人

宁宁应当是一个统一的 **Orchestrator Agent（管家编排 Agent）**，下面连接三套受约束的场景能力：

```text
宁宁编排 Agent
├── 账单分析能力：账本读取、口径计算、异常线索、趋势、报告、预算
├── 理财操作能力：目标补齐、风险测评、适当性筛选、对比、申购／赎回草案
└── 卡片管理能力：卡片状态、安全检查、限额／开关／挂失草案、回执复查
```

不建议让三个独立大模型 Agent 互相对话。金融任务需要统一身份、统一授权、统一确认边界和统一审计；场景差异应放在工具、规则和步骤模板里，而不是放任模型分别决定业务状态。

## 2. 所有任务统一采用六段流程

| 阶段 | 宁宁要做什么 | 页面怎么展示 | 可信结果来自哪里 |
| --- | --- | --- | --- |
| 1. 理解意图 | 识别目标、对象、时间、金额和缺失参数 | 本次任务标题、已识别边界 | 模型意图 + 规则校正 |
| 2. 获取授权 | 只申请本次任务需要的最小权限 | 数据源标签、待授权状态 | 连接状态与 scope |
| 3. 调用信息 | 获取账单、卡片、风险测评、产品或资金状态 | 来源、同步时间、完整性 | 业务沙箱接口 |
| 4. 规划步骤 | 拆解依赖、排序、确定确认点 | 内部任务状态；界面只在需要时显示简短进度或待确认事项 | 场景模板 + 规则 |
| 5. 执行分析／准备方案 | 运行确定性计算；操作类只生成草案 | 进度、约束、待确认标记 | 纯函数／服务端校验 |
| 6. 解释结果与选项 | 解释依据、限制和下一步 | 图表、证据、选项按钮 | 结构化结果 + 模型解释 |

关键操作不在第 5 步自动完成。转账、申购、赎回、调额、挂失、解挂和提高支付权限必须显示“等待用户确认”，进入独立核对页后才能执行。

## 3. 三个场景的功能设计

### 3.1 账单分析

P0 演示主链：

1. 自然语言选择时间和平台；
2. 显示账单授权、来源、覆盖范围、返回条数和质量；
3. 计算消费、普通入账、退款、转入、转出；
4. 展示分类占比、前期对照、较大消费和诊断线索；
5. 每条异常线索可展开真实交易证据和规则说明；
6. 给出“生成明细报告、核对异常、设置预算”三个下一步。

增强功能：月报／年报、预算使用率、周期扣费识别、同日高频、商户聚合、家庭共享账本、可导出的脱敏报告。

可视化：顶部结论卡 + 分类比例条／环图 + 近六个月趋势 + 异常线索卡 + 证据明细抽屉。图表必须能回到纳入统计的交易集合。

### 3.2 理财操作

P0 演示主链：

1. 从对话提取金额、期限、流动性和目标；
2. 缺少风险测评时先完成测评，不能从客群标签推断风险等级；
3. 确定性规则筛掉风险、起购金额、期限或状态不匹配的产品；
4. 最多展示三个候选的收益情景、风险、费用和赎回条件；
5. 用户选择后生成申购／赎回草案；
6. 独立核对页完成适当性、余额、产品状态和用户确认；
7. 只以服务端回执和持仓变化为成功依据。

增强功能：目标储蓄、现金流预测、持仓诊断、到期提醒、情景压力测试、组合再平衡建议。

可视化：目标时间轴、风险／流动性二维对比、三产品对比卡、资产配置条、收益情景区间、申购前后资金变化。

### 3.3 卡片管理

P0 演示主链：

1. 读取脱敏卡片状态、余额、单笔限额、安全开关和近期交易；
2. 对挂失状态、限额、夜间保护、无卡支付和境外交易做安全检查；
3. 从自然语言生成结构化变更草案；
4. 独立核对页展示变更前后、影响和风险；
5. 使用最新 revision 执行，避免旧方案覆盖新状态；
6. 展示回执，并复查最新卡片状态。

增强功能：多卡视图、异常交易确认、临时限额、旅行模式、员工／用途限额、卡申请沙箱预审。

可视化：卡片状态卡、安全评分项、变更前后对比、近期异常时间线、待确认操作条。境外交易和无卡支付在接通对应渠道前只能标为“偏好已保存”，不能宣称已拦截。

## 4. 会话管理和自动上下文压缩

### 4.1 会话模型

每个任务使用独立会话，保存 `id、自动标题、创建／更新时间、归档状态、完整消息、压缩摘要和压缩条数`。用户可以新建、切换、归档和恢复会话。旧版单一聊天数组首次启动时自动迁移为一个会话。

### 4.2 压缩策略

- 页面和本地会话继续保留完整历史，不因压缩删除用户记录；
- 近期 10 条消息原文进入模型；更早消息转成有明确边界的上下文摘要；
- 界面显示“已压缩 N 条早期消息”，避免用户误以为模型仍逐字读取全部历史；
- 用户重置／修改长期记忆后，旧会话通过 cutoff 隔离，不把已纠正或已遗忘的信息重新送入模型；
- 业务真相（余额、持仓、授权、卡状态、账单）每轮从业务系统重新读取，绝不从压缩摘要恢复。

### 4.3 四层记忆边界

1. **当前任务状态**：本轮计划和工具结果，任务结束后可关闭；
2. **会话工作记忆**：本会话摘要和近期消息；
3. **长期偏好／客群上下文**：只有用户主动选择或确认后保存，可查看、修改和删除；
4. **业务状态**：来自支付、银行、产品和持仓系统，不属于模型记忆。

客群标签只调整解释重点和功能排序，不能改变金额计算、风险等级、适当性、权限、限额或确认步骤。

## 5. 本次 MVP 已落地

- 六步任务状态保留在 Agent 内部：理解意图、获取授权、调用信息、规划步骤、执行／准备方案、解释与选项；
- 不再把内部六步清单作为大卡片直接展示；界面聚焦分析结果、数据来源、必要进度和待确认事项；
- 账单、理财、卡片、转账、订阅和一般任务的场景识别；
- 多会话新建、切换、归档与恢复，旧聊天自动迁移；
- 自动标题、完整历史留存、摘要 + 近期消息上下文窗口；
- 理财和卡片任务的场景入口；卡片回复可读取银行沙箱状态；
- 账单结果继续使用确定性计算和可展开证据，模型只负责解释。

## 6. 下一迭代顺序

1. 理财产品目录、风险测评状态机和适当性过滤纯函数；
2. 理财申购／赎回草案、确认页、幂等接口、持仓与回执；
3. 卡片自然语言动作协议、独立确认页、设置回执和失败恢复；
4. 账单月报／年报、预算与可追溯报告；
5. 会话服务端持久化、加密、多端同步和摘要质量评测；
6. Agent 全链路审计事件：任务 ID、数据版本、工具调用、确认人、回执 ID。

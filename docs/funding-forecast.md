# 近期资金安排

入口：知银「资产 → 近期资金安排」，或「订阅 → 查看近期资金安排」。AI 原生首页在发现已授权账户缺口时显示一条简短提示；没有缺口不常驻大卡片。宁宁支持「接下来一周的钱够续费吗？」并提供只读的资金安排入口。

## 功能

- 页面支持 7／14／30 天窗口，列出两个平台的可见余额、窗口内下一笔已知续费、逐笔测算余额以及缺口。
- 微信与支付宝分别计算，支付宝的盈余不会抵销微信零钱的缺口。不使用固定演示银行余额、未来收入或历史账单推断候选。
- 每项签约只计算下一笔已知扣费，不根据月费盲目推演后续周期。日期未知、金额无效、权限不足、签约截断时明确提示信息不完整；已知最低缺口仍可报告。
- 逾期但尚未确认结算的签约暂按仍需支付计一次，展示“已到期，扣款状态待核实”。对应缺口只称“待核实差额”，不是确定的最低补款额，也不是历史扣款失败证据；必须先核实是否已支付，避免重复付款。
- 时间来自已授权账户快照，跟随沙箱时钟；进入页面、回到前台、主动重试及发给模型前刷新。仅授权余额的账户也刷新。同步中或失败时不把缓存当成最新结论，不展示同步时间。
- 模型获得同一份 7 天计算结果、缺失信息和部分扣费依据，不能执行转账、充值、划转或冻结，也不能声称已替用户预留资金。取消仍走既有签约核对流程。

## 数据边界

当前沙箱续费实际使用微信 `wallet.balanceCents`（分）和支付宝 `balance.total`（元转分）。前端仍提示“按平台余额测算，实际扣款渠道请核实”，避免把沙箱结论当成真实平台的银行卡代扣规则。

余额和自动续费各受独立授权约束。无效余额保留未知，真正的零余额保留零。合作方与消息桥最多传递 1,000 项有效签约；截断或省略无效记录时携带 `autopaysIncomplete`，不能据此宣布全部覆盖。资金测算不写账本，不触发结算，也不会自动扩大授权。

## 实现与验收

- `src/lib/funding-forecast.ts`：整数分、日期窗口、缺口和数据完整性模型。
- `src/components/funding-plan.tsx`：窗口切换、分账户测算、扣费明细及数据缺失状态。
- `src/components/steward-chat-home.tsx`：安静首页资金事件与刷新后模型上下文。
- `src/lib/steward-chat.ts`：有限长度资金上下文及 `OPEN_FUNDING` 导航动作。

运行 `npm test`、`npm run build`、`npm run lint`。修改后 `npm run phone:sync` 同步手机内知银。

# 宁宁的任务窗口与共享记忆

## 这版可以怎样使用

AI 原生首页的「任务窗口」打开任务清单。也可以直接交代事情，让模型新建或找到已有任务。经典模式不变。

- 同类事项分别建窗口，例如「今晚聚餐」和「周末旅行」，而不是所有 AA 共用一个聊天。
- 一句话涉及多件事时，先完整拆分原话，再逐项整理。后续事项显示「继续：任务名」，由用户继续查看；未处理的交代保存在服务端，刷新后在对应窗口继续或放弃。
- 关闭自动分配后，交代只送到手动选中的任务。回首页没有选中任务时，仍需自动分配才能确定归属。
- 「收起」只归档对话；可从「已收起」恢复。不取消预约，不结束群收款，不改变余额。
- AA 窗口首次使用仍需选择、授权微信群和参与人。以后读取其关联账本；旧账本可通过窗口内「继续记录」关联，不复制消费。

建议测试：先建并关联「今晚聚餐」AA，记录「饮料18」。然后说「明天给妈妈转500，刚才饮料改成16」。应分为转账与原聚餐任务；转账需要核对授权，饮料修改只作用于原账本。

## 三层数据，各负其责

| 层 | 内容 | 不承担什么 |
| --- | --- | --- |
| 任务窗口 | 标题、类型、状态、待处理原话、对话、较早交代摘录、AA账本关联 | 不充当资金回执或支付授权 |
| 业务数据 | 银行预约及回执、AA账本及微信收款结果、订阅实际状态 | 不靠聊天文本推断成功 |
| 长期记忆 / 画像 | 用户启用并允许保留的偏好、习惯、目标、背景与暂定印象 | 不把「今晚李娜半份」自动当成永久习惯 |

这不是多子代理系统。一个模型负责分流，现有各业务流程继续办理；每次业务对话只带当前任务上下文。

## 记忆如何维护

沿用原有服务器长期记忆、来源原话、有效期、用户修改/删除/停用能力，不另建一套画像。普通任务和 AA 都读取共享记忆。AA 中共享偏好仅用于表达与建议，不覆盖活动确认过的金额、垫付人和参与人。

非日常任务不自动观察并写入用户画像；显式记忆候选仍需用户确认。记忆版本发生变化时，旧版本任务对话和摘录不再作为模型上下文回灌。原对话仍可查看，不代表删除审计历史。AA 的临时追问历史也随记忆上下文重置而清空。

当前每个任务最多保留40条消息；更早的用户交代保留为有界原文摘录（6000字符，模型每轮最多读取其中1500字符）。这不是语义知识库，也不是完整永久聊天档案。长期记忆仍以现有规则检索、过期过滤和用户维护为主，**本次没有实现语义去重/冲突合并或后台自主画像整理**。

## 持久化与安全边界

- `/api/zhiyin/workspaces`：GET读取，POST执行create/turn/enqueue/discard/status/rename/link。
- 与AA账本共享当前浏览器的沙箱scope；服务端文件 `.zhiyin-workspaces-<scope>.local.json`，Git忽略且静态访问阻断。
- 同源校验、请求体限长、类型校验、乐观版本、请求ID去重、文件锁与原子替换。
- 任务最多100个、每任务最多20条待处理交代；超限明确报错，不静默丢弃。
- 模型路由校验任务ID、类型、原话逐段覆盖及顺序。格式/覆盖错误可重试一次；再次失败保留输入，允许用户手动选择。语义分流仍受模型判断影响，不能声称永远准确。
- 打开历史窗口不会自动恢复可执行的旧金融按钮；可重新交代继续办理，重新读取实时数据并核对。真实执行状态始终以原业务页面为准。
- 这是单机比赛沙箱：scope不是登录认证；长期记忆和银行服务仍沿用已有单用户结构，不是生产级多租户系统。

## 验证入口

`npm test`：任务隔离、同类独立、记忆版本、混合请求、待处理恢复、AA加载竞态、接口校验、版本冲突、其他功能回归。

`node scripts/workspace-smoke.mjs`：Chrome独立测试环境，真实任务API，模拟模型回复；验证拆分、切换、刷新以及手机/桌面界面。

`node scripts/workspace-router-live-smoke.mjs`：调用控制台已配置的真实模型做合成请求分流，业务回复模拟，不发起资金操作。需要3000端口运行，测试任务使用独立scope。真实模型非确定性，失败应记录并分析，不能用模拟测试代替。

# Steward reply presentation

The native home gives the current response the main stage and temporarily hides its idle summary. Closing the response restores the home. Classic mode is unchanged.

Bill replies use the exact authorized `BillAnalysis` snapshot calculated for that request, never amounts extracted from model prose. Source, period, expense, ordinary inflow, category proportions, large purchases and separate refund/transfer flows are visible or expandable. Missing authorization, empty records and ambiguous periods fall back to the explanation, rather than presenting an unsupported zero-value report.

The result snapshot is session-only; history continues to persist text, not financial result objects. Existing history gains safe paragraph, heading, list and bold rendering. HTML is never interpreted. A new bill question is required to generate a new structured report after reload.

Native details controls provide keyboard access. Reduced-motion users get no report entrance animation. The result start is the scroll target; errors retain their recovery target. Figures use the existing teal/ink system and tabular numerals.

Verification: 206 root tests passed; TypeScript/build and phone sync succeeded. Two independent critique agents observed the old same-weight text rendering, but both hit account usage limits before complete review reports. Their partial observations are not a completed design verdict.

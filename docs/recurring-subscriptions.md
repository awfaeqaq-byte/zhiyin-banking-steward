# 历史账单订阅识别

知银将两类数据分开管理：支付平台提供的**自动续费签约**，以及历史账单推断的**疑似周期扣费**。前者可以核对后取消；后者只能确认、忽略或恢复核对，不会创建签约，也不能直接触发扣费或取消。

## 使用与验证

1. 从 MobileGym 打开知银，在账户连接中连接微信支付或支付宝；双方确认授权，至少包含「读取交易账单」。若还要查看、取消平台签约，需要「自动续费」权限。
2. 进入「订阅」查看「账单中的周期扣费」。展开依据可以核对每笔日期和金额；「这是订阅」「不是订阅」会保存到当前浏览器，支持重新判断。
3. 在 AI 原生首页问宁宁「帮我检查账单里可能的订阅，说明依据」，或「这项订阅值得保留吗？」。每次提问前同步授权数据；宁宁收到平台签约、未忽略的候选以及历史扣费证据。没有使用频率数据时，应先问用户，不能编造“长期没用”。
4. 已签约服务的取消仍需用户在确认面板核对，平台确认成功后才更新状态。

本次未向用户的账本注入演示记录。测试疑似识别时，可在微信支付的记账本手动录入同名服务的三期记录（确保记账本设置包含手动记录）。以 2026-09-22 为例，分别录入 7 月 15 日、8 月 15 日、9 月 15 日的「云盘会员」支出 18 元，可得到预计 10 月 15 日的候选；只有一笔付款不够判断。不要使用已签约自动续费产生的记录验证“未知候选”，它们会被排除。

## 识别规则与边界

- 按平台和规范化商家名称分组，至少三期连续、等间隔的付款，支持月／季／年；金额偏离中位数不超过 5%，日历日期允许 3 天浮动，并处理月末和闰年。
- 同一商家的全部已读取记录参与判断；不会从零散日常消费中挑三笔凑规律。同月多笔或缺期会使该组不通过，因此当前偏保守。
- 去重、排除收入／转账／退款及关联原付款、无效／未来日期；已知签约和已取消签约的关联扣费不会成为新候选。
- 预测仅推进一期，超过预计日期 3 天仍没有新扣费就停止展示；预测不是实际扣费通知或平台承诺。
- 双方交易适配器均按时间读取最近最多 1,000 笔。微信内置后端读取跨月历史；第三方旧适配器未实现历史接口时，回退读取最近 13 个月，年付样本可能不足。
- 模型接收结构化识别结果和证据，不是让模型直接自由扫描整个账户。提示词最多 4,000 字符，优先保留当前问题点名的项目，并明确未展示数量；对话请求也受整体字节预算约束。
- 只使用已授权数据，不自动扩权。确认／忽略保存在 `zhiyin-recurring-reviews-v1`，不修改原账单。
- 这是沙箱支付数据上的功能，不代表已连接真实微信或支付宝，也不包含离线后台推送。

## 开发入口

- `src/lib/recurring-payments.ts`：纯识别引擎。
- `src/components/recurring-subscription-review.tsx`：证据与用户核对。
- `src/lib/steward-chat.ts`：模型证据、提示词、动作验证。
- `mobilegym/apps/Zhiyin/finance-access.ts`：已授权跨月历史与取消标记。

运行 `npm test`、`npm run build`、`npm run lint`；修改后用 `npm run phone:sync` 同步手机内的知银。

# 理财建议的数据来源与 AKShare 接入

> 版本：MVP v2，2026-10-09  
> 原则：适当性由用户约束和银行规则决定；AKShare 只补充外部市场环境，不替用户做风险选择。

## 1. 一条建议必须说明四类依据

| 优先级 | 数据 | 可信来源 | 在建议中的作用 |
| --- | --- | --- | --- |
| 1 | 金额、期限、目标、流动性、用户主动确认的风险承受范围 | 本次对话与风险测评 | 决定能否进入候选 |
| 2 | 可用余额、账单现金流、近期刚性支出、现有持仓 | 银行与已授权账单接口 | 检查是否挤占日常资金、是否过度集中 |
| 3 | 产品风险等级、起购额、期限、费用、赎回规则和在售状态 | 银行产品目录与正式产品文件 | 适当性过滤和操作核对的唯一产品事实来源 |
| 4 | 指数、市场利率等外部环境 | AKShare 标准化适配器 | 解释市场环境、波动和执行节奏，不提高风险上限 |

因此，外部行情上涨不能把谨慎型用户推到高风险产品；AKShare 缺失时，系统仍可完成适当性筛选，但必须明确“外部环境数据暂不可用”。

## 2. 已实现的 AKShare MVP

1. 页面首次打开只读取本地缓存，不自动发起大量网络请求；
2. 用户点击“检测更新”后，先请求单一沪深300序列作为小样本；
3. 小样本成功后，再获取沪深300摘要和 Shibor 3个月利率；
4. 每个数据源单独记录 `ready / empty / error`，部分失败时保留已经验证的数据；
5. 结果归一化后缓存到本机文件，12 小时后标记为过期；
6. 前端只展示日期、数值、涨跌和数据边界，不把它包装为收益承诺。

本机安装命令：

```sh
./scripts/setup_akshare.sh
```

运行时默认使用 `.venv-akshare/bin/python`；也可以通过 `AKSHARE_PYTHON` 指向已有 Python。AKShare 依赖环境和市场缓存均被 Git 忽略。

## 3. 本次基金小样本试拉

只读的 `/api/zhiyin/fund-samples`：页面先读本机缓存，用户点击“更新基金市场样本”才发起网络请求。爬取范围固定为三只已有资料样本，不接受任意代码作为抓取代理。现在优先读取发行方页面，110006 取万份收益与历史七日年化，026197 和 510330 取单位净值；后两只再用 AKShare 对同日单位净值做交叉核对。同日数值不一致时返回 `conflict` 并隐藏数值；发行方访问失败可保留旧值，但标为过期。各产品分别处理，互不拖累。

2026-10-09 本机实际试拉：110006 的 10-08 万份收益 **0.2437 元**、七日年化 **1.002%**，来自[易方达披露页](https://www.efunds.com.cn/fund/110006.shtml)；026197 同日单位净值 **0.9852**，与[易方达披露页](https://www.efunds.com.cn/fund/026197.shtml)及 AKShare 同日数据一致；510330 同日单位净值 **4.5699**，与[华夏基金披露页](https://www.chinaamc.com/fund/510330/index.shtml)及 AKShare 同日数据一致。万份收益、七日年化和单位净值含义不同，不能比较数值高低，也不是交易报价或收益预测。第三方接口说明见 [AKShare 公募基金文档](https://github.com/akfamily/akshare/blob/main/docs/data/fund/fund_public.md)。

| 方案 | 获取内容 | 成本和限制 | 本项目用途 |
| --- | --- | --- | --- |
| [AKShare](https://github.com/akfamily/akshare) | 包装东方财富等公开页面的基金净值、ETF 行情 | 库免费；底层页面接口可能变动，其[项目说明](https://github.com/akfamily/akshare/blob/main/docs/introduction.md)明确提示学术研究及商业使用风险 | 比赛沙箱的小规模历史样本 |
| [Tushare Pro](https://tushare.pro/document/2?doc_id=119) | 标准化 `fund_nav`；也提供[基金列表](https://tushare.pro/document/1?doc_id=19) | 这些接口目前要求至少 2000 积分，不能当作无门槛免费接口 | 获得许可与积分后可替换适配器 |
| [基金发行方官网](https://www.efunds.com.cn/fund/026197.shtml) | 官方产品说明、费率、净值、公告 | 页面通常公开，但没有统一免费 API；逐站核对使用条款和更新频率 | 三只白名单样本的首要事实来源 |

当前做法不是对全市场爬取或提供生产行情服务。若产品要正式上线，应取得明确的数据分发授权，并把发行方公告、交易状态、费率和订单渠道分别接入受控系统。

## 4. 下一步最值得做的智能功能

- **目标缺口计算**：结合目标金额、目标日期、当前可用资金，给出每月需要保留多少，而非只列产品；
- **应急金门禁**：从账单估算必要支出，但必须让用户确认家庭责任与应急月数，再决定可投资金额；
- **现金流情景**：展示“正常／收入下降／临时大额支出”三种情景下的资金余量；
- **可解释比较**：每个候选明确“为何适合、为何没选其他产品、使用了哪些数据、哪些数据缺失”；
- **持仓体检与到期任务**：集中度、流动性缺口、到期时间线和再确认提醒；
- **主动但克制的管家提醒**：只对异常变化、目标偏离和待确认事项提醒，避免把行情波动变成频繁营销。

## 5. 生产化前的边界

- 比赛 MVP 使用 AKShare 做公开市场数据验证；生产环境应增加供应商许可、可用性 SLA、行情时间戳和数据血缘；
- 产品名称、风险等级、费用、额度和可售状态不能来自 AKShare，必须来自银行受控产品系统；
- 申购／赎回仍使用独立确认页、服务端适当性校验、幂等请求和正式回执；
- 客群长期记忆只调整解释方式与排序，不得替代风险测评或自动扩大权限。

## 2026-10-02 — 以自然语言为核心的个人金融 Agent 首页

- 关联场景：账单分析、资金规划、订阅识别、长期关注、会话管理
- 更新前问题：首页以“待确认线索”和固定功能卡片为主，用户要先理解产品模块再提问；同步时间进入 10 月后，9 月 29 日结束的测试账单会被误判为“本月 0 笔”。
- 本次实现：首屏改为财务速览、主对话输入、动态问法示例、AI 最近发现和“我的关注”。账单、分析、资金规划、订阅只作为原始数据与历史的辅助入口。普通变化直接形成洞察，只有重复扣款、余额缺口和异常交易等事项进入“需要你确认”。
- 个人化：用户可以直接说“以后外卖每月超过 800 元提醒我”、“发现新的自动续费时告诉我”或“停止关注打车支出”。规则以结构化数据保存在本机，可在首页查看和删除；普通账单问题不会被误存为长期关注。
- 账期一致性：账单分析优先使用数据覆盖截止日，其次使用最后一笔交易日，无交易时才回退到同步时间。官方微信测试账单现按 2026-09-29 作为“本月”基准，首页成功显示支出 ¥12,284.17、收入 ¥23,396.31 和预计结余。
- 会话边界：重新打开 App 或收起当前回复时回到 Agent 首页；历史会话仍按任务分离保存，只在用户主动展开时显示。
- 自动化测试：43 个测试文件、289 条测试全部通过；ESLint、TypeScript、根项目生产构建、知银手机同步和 MobileGym 生产构建通过。

## 2026-10-01 — Mastra 调度、异常复核与目标规划闭环

- 关联场景：账单分析、理财操作、Agent 自动任务、人工确认与审计
- 更新前问题：自动任务只保存在浏览器并模拟运行，关闭页面后没有服务端计划；异常账单只有分析结论，不能逐条确认；理财操作缺少围绕具体目标的资金缺口规划。
- 本次实现：接入 `@mastra/core 1.72.0` 和 `@mastra/libsql 1.24.0`，新增每月账单报告、每周理财与现金流体检、每日异常账单复核三个 Workflow，并用原生 Schedule 持久化 cron、暂停与恢复状态。自动任务页面新增最近运行、触发方式、依据和决策审计。
- 人工确认：异常复核使用实际授权账单规则产生候选，工作流进入 `waiting_confirmation`；用户逐条选择“需要关注”或“排除线索”，全部处理后才变为完成。金额较大和同日高频只作为线索，不直接判断欺诈。
- 理财规划：新增目标名称、目标金额、已准备金额和计划月数输入，生成保守／基准／积极三种压力测试情景；假设年化仅用于测算，不属于市场预测或收益承诺。
- 数据与安全边界：服务端只保存任务运行所需的最小授权摘要，原始账单仍由现有连接层管理；Workflow 不会自动扣款、申购、赎回或修改卡片。`.zhiyin-mastra.db*` 和 `.zhiyin-automations.local.json` 均被 Git 忽略并禁止静态访问。
- 真实验证：从官方微信年度账单的最近交易月份生成 4 条复核线索，包括 2 笔较大消费和 2 组同日高频交易；成功确认其中一条并写入审计。目标规划默认示例显示 5 万元目标、已准备 1 万元、12 个月的三情景月度准备金额。
- 自动化测试：41 个测试文件、283 条测试全部通过；ESLint、TypeScript 和根项目生产构建通过。生产依赖 `npm audit --omit=dev` 为 0 个已知漏洞。
- 已知限制：本机服务或电脑关闭时不会执行任务；尚未实现错过任务补偿、系统通知、失败重试策略和生产密钥托管。
- 下一步：部署常驻 Worker 与低打扰通知；随后把资金操作确认接入可恢复工作流，并补充模型调用与费用可观测性。

## 2026-09-29 — 宁宁任务规划、多会话与上下文压缩 MVP

- 关联场景：账单分析、理财操作、卡片管理、通用 Agent 交互
- 更新前问题：所有聊天记录保存在一个数组中；用户看不到宁宁如何理解目标、核对授权、调用数据和安排步骤；长会话只做固定条数截断；理财与卡片任务缺少明确入口和确认边界展示。

- 自动化测试：新增任务识别、确认边界、旧记录迁移、任务恢复和上下文压缩测试；根项目全量 267 条测试通过，后续恢复细节相关 31 条测试通过；根项目生产构建与手机同步通过。

## 2026-09-29 — 修复知银账单空快照并自动连接测试账本

- 关联场景：知银对话式账单分析、微信账单本机回放
- 更新前问题：微信记账本已经载入 Excel，但知银 iframe 的连接状态仍为空；模型收到的 `billAnalysis` 因此为 0 条并错误提示重新授权。
- 根因：账单只写入 MobileGym 微信 store，没有同步建立知银的 `zhiyin-connections` 快照；父页面和 iframe 的初始化顺序还会造成旧空状态覆盖。
- 本次实现：本机账单加载后自动建立仅含 `transactions` 的微信测试授权与连接快照；知银 iframe 启动后再通过手机桥恢复一次已授权数据，消除 localStorage 初始化竞态。移除本机账单配置时会清理自动创建的测试连接。
- 验证结果：重新打开知银后首页识别到微信数据；实测提问“分析我2026年9月的微信账单”返回 158 条期间记录、消费支出 ¥11,938.09，并展示其他、购物、交通、餐饮分类；不再返回 0 条。
- 自动化测试：手机同步构建通过；电话桥、账单分析、聊天首页及手机集成共 64 条测试通过；MobileGym 生产构建通过。
- 口径说明：¥11,938.09 是知银消费口径，转账单列；微信记账本的 ¥12,020.89 是包含转账等支出方向的页面汇总，两者差额不是漏数。

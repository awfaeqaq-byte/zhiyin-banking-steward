# 任务日历

本页记录已实现的局部功能与视觉事实。它扩展知银现有浅底、墨蓝文字与克制青色的界面，继承根 `PRODUCT.md` 的用户控制与资金授权原则；不建立新的设计系统，也不替代根 `DESIGN.md`。

## 入口与使用

- 首页顶部“任务日历”图标及个人中心中的“任务日历”行进入日历。
- 在管家对话中提出带明确时间的提醒，例如“明天早上9点提醒我核对这个月的账单”。`prepare_task` 返回提醒草稿，回复明确显示“尚未创建任务”；点击“核对并保存提醒”进入表单，用户再点击“确认保存提醒”才写入。`open_tasks` 提供打开日历的入口。
- 日历支持上月、下月、今天与选择日期；月历下方或右侧显示当天议程。可直接“添加提醒”，填写名称、北京时间及选填说明。
- 展开待处理提醒后可标记完成、修改，或经二次确认取消。已完成和已取消的提醒保留记录，不能再次修改；取消项不显示月历标记。
- 首页仅在有到期且待处理的自建提醒时显示提示，点击进入第一项到期提醒对应的日期。首页不常驻完整月历；对话发送中、回复展开及历史视图期间不显示该提示。

## 日程来源与权限边界

| 来源 | 日历内容 | 操作边界 |
| --- | --- | --- |
| 自建提醒 | 用户确认保存的标题、时间、说明与处理状态 | 仅记录和提醒，不能触发转账或扣费 |
| 银行预约 | 从银行预约状态派生的执行时间、收款人、金额及状态 | “管理预约转账”回到银行业务流程；执行由原银行预约系统承担 |
| 订阅续费 | 已授权 `autopay` 范围且具有有效 `nextChargeAt` 的订阅 | 已取消授权项排除；“查看订阅”回到订阅管理，实际扣费以平台账单为准 |

续费到期后显示“扣费结果待核实”，不会凭时间推断已扣款。没有截止日期的 AA 等业务不捏造日程。提醒、银行预约和续费使用来源文字及图例区分，不只依赖颜色。

当前提醒是单次时间点，不支持重复规则、系统推送或后台通知。到期提示会持续存在，直到用户完成或取消；“单次”并不表示只展示一次。首页提示挂载时读取数据，每 30 秒刷新，并响应任务更新与手机前台事件。日历进入时及窗口恢复焦点、手机前台事件时重新加载。所有日期展示和输入解释均按北京时间（UTC+8）。

## 局部视觉与响应式

操作型页面延续现有浅色界面。青色用于主按钮和选中日期；银行预约以蓝色标记，续费以暖棕色标记。日期选择仍配有按下状态、今日标识和文字标签。选中日期上的标记统一变为白色，来源以议程文字确认。

桌面内容最大宽度为 1040px，月历与议程为等宽双栏，栏间距 36px。700px 及以下改为月历在上、议程在下的单栏，间距 18px，议程顶部用细分隔线组织层级。月历以周一开始，显示完整周及相邻月份日期；没有安排时提供直接添加提醒的空态入口。

组件采用平面色块和细分隔线，不另加卡片阴影。按钮至少 44px 高，日期按钮桌面至少 48px、手机至少 46px；键盘焦点有清晰青色轮廓。编辑表单以淡青背景及圆角聚合，保存按钮明确标出动作。加载、重试、保存中、完成、取消、银行执行失败和空态均有对应文本。此处尺寸和颜色角色仅记录日历局部事实，不升级为全局约束。

## 数据与 API

自建提醒通过 `GET /api/zhiyin/tasks` 读取，通过 `POST /api/zhiyin/tasks` 保存或变更状态。客户端验证响应结构并设置 8 秒请求超时。服务端由 Vite 开发及预览服务注册，数据持久化到项目根 `.zhiyin-tasks.local.json`；纯静态托管不会提供该 API。

状态包含递增 `revision` 与任务数组。保存采用排他锁、临时文件及原子重命名；版本冲突返回 409，避免旧页面覆盖较新的记录。文件损坏时保留原文件并报错。POST 要求 JSON、自定义请求头及同源检查，限制正文 4096 字节。任务最多 1000 条，标题最多 80 字、说明最多 500 字；新增和修改要求未来的有效时间。持久化文件的直接 URL 访问被拦截。

这些是本地原型的访问保护，不是生产多用户认证或账户隔离。提醒存储与银行资金执行分离，AI 草稿不直接调用任务写入，也不获得额外金融授权。

# 支出诊断（沙箱）

## 数据链路

授权交易 → 校验金额/日期/ID → 同平台 ID 去重 → 确定性分类别名归一 → 消费与退款/转账分离 → 金额、频次、周期候选 → 前期对照 → 模型解释。

相似金额、商户、时间不是删除交易的依据。跨平台流水不自动合并；退款不抵扣消费。清洗计数针对本次返回且截至查询结束日期的数据（包含用于对照的历史），不是当月笔数。

## 当前规则与边界

- 金额：本期至少 5 笔消费；单笔达到 1,000 元且达到本期中位数的 3 倍。它是大额线索，不是欺诈判断。
- 频次：同平台、同商户名称、同日至少 3 笔独立消费。不能据此认定重复扣款。
- 周期：同平台、同商户最近 3 笔，间隔均为 25–35 天，最大/最小金额不超过 1.1，最近一笔在查询期内。需要用户确认，不等同已开通自动续费。
- 趋势：查询期之前的等长时段，仅对比返回记录；缺少前期消费时不算百分比。数据完整性未知，不称为完整月环比。
- 分类：只合并明确的分类别名，不根据商户名称猜测用途。尚无用户自定义标签或跨平台交易实体匹配。
- 首屏最多展示 5 条线索；金额线索最多 2 笔。数量不是所有潜在问题的穷尽检查。

## 展示和模型

首屏以简短解释为主，不固定铺出候选线索或支付历史。模型仅在解释需要佐证时引用 `[[evidence:N]]`（本次提示词提供的 1–3 编号）；前端在相应句子后展示该组真实交易，不接受模型自编的交易数据。重复、越界引用忽略；未引用则不展示，不出现固定的“还在用”等按钮。

金额和分类、前期对照、退款转账、数据质量按需展开。模型要求不复述汇总、不生成表格、不编造用途或环比。模型仍可能不遵循格式；旧回复表格保留横向行列，表头仅一次，默认前 4 行，其余可展开，窄屏在表格内横向滚动。不执行 HTML。历史回看没有本次账单快照时仅显示文字，隐藏引用标记。

现有历史回复不重跑模型；重新提问以获取新诊断。自动分析不会发起支付、取消订阅或对原账单进行删除操作。

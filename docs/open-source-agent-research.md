# 开源 Agent 框架调研与知银采用建议

> 调研日期：2026-10-01
> 目标：为账单分析、理财规划、自动任务、长期记忆和关键操作确认选择可落地的 Agent 能力。

## 结论

当前项目不需要三个相互对话的自由 Agent。建议继续使用一个宁宁编排 Agent，把确定性业务能力做成工具，并把周期任务做成受控工作流。

项目已采用 **Mastra**：它与现有 TypeScript/Node 技术栈一致，并提供 Workflow、存储和原生 Schedules API。账单月报、理财周检和异常复核已经封装成工作流；开放式追问和解释继续由宁宁处理；申购、赎回与卡片变更仍走确定性接口和本人确认。

## 已落地状态

- `@mastra/core 1.72.0` + `@mastra/libsql 1.24.0`，时区固定为 `Asia/Shanghai`。
- 三个服务端 Workflow：每月账单报告、每周理财与现金流体检、每日异常账单复核。
- Schedule 支持持久化创建、暂停、恢复和服务端立即运行；重启开发服务后计划仍保留。
- 运行记录保存触发方式、结果、依据和人工处理状态。异常线索逐条确认，全部处理后任务才完成。
- 前端只同步最小必要摘要；原始账单仍由现有授权适配器管理。定时任务不执行资金、持仓或卡片变更。

## 候选比较

| [Mastra](https://github.com/mastra-ai/mastra) | TypeScript；Agent、图式 Workflow、记忆、暂停／恢复；1.50.0 起支持 Agent 与 Workflow 的计划任务 | 很高：可以直接进入现有 Node 服务层，支持本项目的兼容模型配置 | 下一阶段首选，先替换自动任务调度层，不重写业务规则 |
| [LangGraph JS](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph) | 状态图、节点级检查点、重试、`interrupt()` 人工确认、长期运行恢复 | 高：金融流程控制成熟，但开源运行时本身仍需配调度器和持久化 | 当任务分支、重试与回放明显复杂后再评估 |
| [OpenAI Agents SDK JS](https://openai.github.io/openai-agents-js/) | TypeScript；工具、会话、可序列化 RunState、审批中断与恢复 | 中高：确认机制清晰，适合模型与工具编排；原生重点不是 cron 调度 | 若后续统一到 OpenAI Responses／Agents 生态可采用其会话和审批层 |
| [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) | Python／.NET；图工作流、检查点、HITL、可观测性、MCP／A2A | 中：企业能力完整，但会引入新的 Python 服务栈 | 若团队后端转向 Python 或需要企业级多 Agent 编排再采用 |
| [AutoGen](https://github.com/microsoft/autogen) | 多 Agent 对话与工具调用 | 低 | 官方已进入维护模式，新项目不采用，转看 Microsoft Agent Framework |

## 适合知银的四个工作流

### 1. 每月账单管家报告

```text
定时触发 → 检查账单授权与完整性 → 确定性统计 → 异常线索规则
→ Agent 生成通俗解释 → 保存报告 → 有重要变化才提醒用户
```

模型不计算金额，也不能把“未返回数据”说成“没有消费”。报告必须保存数据来源、覆盖区间和规则版本。

### 2. 每周理财与现金流体检

```text
定时触发 → 读取余额、持仓、近期固定支出 → 读取 AKShare 市场摘要
→ 检查目标偏离与流动性缺口 → Agent 解释 → 给出可选下一步
```

定时任务只能产生建议和待确认事项。风险等级必须由用户主动确认；外部行情不能提高风险上限；任务不得自动申购或赎回。

### 3. 账单异常核对任务

异常规则产生候选后建立一个可暂停任务。用户可以确认“本人消费／需要继续核对／忽略此类”，工作流从检查点继续，而不是重复读取和解释全部账单。

### 4. 到期与目标任务

持仓到期、目标日期接近或现金缺口发生显著变化时创建任务。普通行情波动不触发高频提醒，避免把智能管家做成营销推送。

## 分阶段接入

1. **已完成：服务端 MVP**：LibSQL 保存 Mastra Schedule，独立状态文件保存最小任务上下文和最近 50 次审计记录。
2. **已完成：Mastra 调度层**：使用 Schedule CRUD 管理 cron；账单、理财和异常复核分别封装为 Workflow。
3. **已完成：异常确认与审计 MVP**：候选线索进入等待确认状态，用户可标记“需要关注”或“排除线索”。
4. **下一步：生产 Worker 与通知**：部署常驻服务、错过任务补偿、失败重试和低打扰通知；本机关闭服务后不会执行。
5. **下一步：资金操作恢复点**：申购、赎回或支付前 suspend，恢复时校验用户、任务、参数和幂等键。
6. **下一步：完整可观测性**：记录工具调用、输入数据版本、模型版本、费用和失败重试。

不要一开始引入多 Agent 群聊。对于当前三个场景，规则工具 + 一个编排 Agent + 可暂停工作流更容易验证，也更符合金融操作的责任边界。

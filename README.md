## 本地运行（手机沙箱）

```sh
npm install
npm --prefix mobilegym install
npm run phone:dev
```

打开 http://127.0.0.1:3000 ，在手机桌面点击「知银」。知银只在 MobileGym 手机会话中运行；页面和本地规则无需 API Key 即可体验。宁宁的大模型对话可在“沙箱控制台 → 模型配置”中填写兼容服务。密钥不写入仓库。

自动任务依赖 Node.js 22.13 或更高版本。计划和运行元数据保存在被 Git 忽略的 `.zhiyin-mastra.db` 与 `.zhiyin-automations.local.json`；开发服务运行时，Mastra 会按 Asia/Shanghai 时区执行启用的任务。

```sh
npm run build   # 类型检查与完整手机生产构建
npm run lint    # 代码检查
npm test        # 交互回归测试
```

## 手机沙箱（MobileGym）

完整框架源码在 `mobilegym/`，知银作为手机 App 接入。`src/` 是手机 App 内嵌页面的源代码，由 `phone:sync` 编译到 MobileGym；不再提供独立网页启动入口。

```sh
npm run phone:dev      # 构建知银并启动手机：http://localhost:3000
npm run phone:sync     # 修改知银源码后重新同步，再刷新手机模拟器
npm run phone:build    # 构建知银和整部手机
npm run phone:preview  # 预览已构建的手机
```

手机底部短横线上滑返回桌面；左右边缘向内滑返回上一层。可打开微信、支付宝、电话等框架自带的模拟应用，再从桌面回到知银。知银使用独立 WebView 保留原有 UI，经典款 / AI 原生仍在「个人中心 → 设置 → 使用模式」切换。

本机微信账单回放通过仓库根目录的 `.zhiyin-bill-source.local.json` 配置绝对 `sourcePath` 和 `expectedSha256`，该文件被 Git 忽略。默认使用现有沙箱数据，不在启动时导入：打开“沙箱控制台 → 财务测试 → 本地 Excel 账单回放”，手动确认后才启用，先备份本浏览器原账单。它不会自动授予知银权限；需要在知银连接设置完成双方授权。点击“恢复原账单”关闭后台回放、还原备份并保留回放期间新产生的消费。不要用删除配置代替恢复。回放开关是本地服务共用，浏览器备份各自独立。定时月报在回放开启且获得来源授权后重新读取、校验 Excel；缺失配置、授权或哈希变化时留下失败记录。支付宝和普通浏览器沙箱账本尚无离线读取适配器。“本月／近7天”以沙箱当前日期为准；历史样本请明确指定月份。完整校验口径见 [微信账单一致性与客群记忆设计](docs/wechat-bill-consistency-and-customer-memory.md)。

官方完整素材包解压在 `mobilegym/mobilegym-data/`，本地服务通过 `/cdn/` 加载壁纸、小组件等资源；压缩包也保留在该仓库根目录。不把这些大文件提交进 Git。支付宝默认图标使用上游仓库已有图片，替换了简化线稿。

目前已接通 App 启动、后台保留、返回导航和只读通讯录选择。知银首次读取通讯录时会申请系统权限，只接收姓名、头像色和手机号后四位；“妈妈（6621）”与“爸爸（7316）”可匹配演示银行收款账户，其他联系人只展示未匹配状态。知银仍不读取联系人备注或完整号码，也不与微信、支付宝共享余额、交易或消息；没有真实账户登录、资金操作或跨 App 自动执行。框架不是 Android 虚拟机，不能安装任意 APK。

MobileGym 源码遵循 Apache-2.0；素材数据另遵循 CC BY-NC 4.0，并受第三方权利限制。保留 `mobilegym/LICENSE`、`LICENSE-DATA`、`NOTICE` 及素材包免责声明；详情见 `mobilegym/docs/zhiyin-integration.md`。

## 可体验的流程

- 通讯录选人：在经典款转账表单或 AI 原生的「修改安排」中点击「从手机通讯录选择」，允许系统只读通讯录权限，然后选择妈妈或爸爸；选择只回填收款人，不会发起转账。
- 「个人中心 → 设置 → 使用模式」选择经典款或 AI 原生：保留原有页面与操作，管家选择和卡片设置共用；模式选择会保留，首页不展示模式开关。
- 管家首页：资产显隐、需求输入、快捷场景、通知与待办。
- 管家切换：宁宁 / 阿衡，头像、称呼与提示文案同步变化；浏览器刷新后保留选择。
- 转账演示：整理方案 → 修改金额、收款人和日期 → 核对 → 模拟预约 → 撤销。
- 消费分析：按授权交易生成月度／年度报告、分类、趋势和交易依据。
- 理财方案：五项风险测评、产品筛选与对比、确认申购、持仓查看和赎回；沙箱申购与赎回使用本机银行资金账本。
- 银行卡：单笔支付限额、交易保护开关、模拟挂失与恢复，以及确认提交沙箱卡申请。
- 我的：偏好记忆删除与恢复、隐私开关、帮助说明。

## AI 原生模式演示

1. 点击首页右上角个人图标（经典款也可通过底栏“我的”），进入「设置 → 使用模式」选择「AI 原生」，返回首页后点击示例或输入「下周五给妈妈转2000，再帮我留够信用卡还款的钱」。
2. 查看同一张事务卡：转账 ¥2,000、还款预算 ¥12,000、预计自由资金 ¥16,360。
3. 输入「改成3000」，原卡更新为 ¥15,360，并显示变化；点金额或日期只编辑对应字段，“修改安排”可调整完整方案。较早指令默认折叠，资金不足时显示明确缺口并禁止授权。
4. 麦克风入口提供本地语音交互演示：按住、松开、核对示例文字，再发送；上滑或关闭可取消，不会申请麦克风权限。
5. 「前往授权」进入独立核对弹层，「确认模拟授权」生成演示预约回执。可修改（先撤销旧授权）或撤销，也可通过顶部「事务」找回草稿和预约。

本次可安排资金 ¥30,360 = 经典款现金 ¥42,300 − 日常生活预算 ¥11,940；还款预算不是冻结余额。为避免多笔示例重复分配同一份资金，演示同时只允许一笔已授权预约。经典款的挂失和支付限额也会阻止原生模式授权。

## 演示边界

所有人物账户信息、资金、流水、分析及金融方案均为虚拟演示内容，不构成金融建议。没有真实银行连接、真实支付或身份认证。管家聊天通过服务端代理调用配置的模型，支付数据来自本地手机沙箱。

经典场景的输入分流仍使用本地关键词；AI 原生管家对话已接通模型。语音输入是示例交互；管家试听使用设备内置中文语音，不是角色正式配音。本机账单回放会由开发服务器只读解析已配置的 Excel，不上传到第三方；模型只接收用户授权范围内的规范化结果。

管家、偏好列表、界面模式及 AI 原生事务保存在当前浏览器的 localStorage；银行卡设置、卡申请和理财沙箱操作共用本机服务的银行资金账本，申购扣款与赎回入账会更新银行卡余额。境外交易开关可通过银行卡页的 ¥1 境外沙箱付款验证，不会发起真实跨境支付。请勿输入真实账户或敏感信息。原生模式固定以 2026-09-13 为演示当天，「下周五」为 9 月 18 日；支持示例中的有限指令，不是通用自然语言理解。未配置本机账单时使用内置演示数据；配置后按导入报告展示有效明细和隔离数量。

## 结构

- `src/App.tsx`：场景页面、模拟数据与交互状态。
- `src/index.css`：响应式布局和视觉样式。
- `src/components/ui/`：按钮、开关、弹窗基础组件。
- `src/components/native-banking.tsx`、`native-banking.css`：AI 原生事务、对话、编辑、语音演示和授权界面。
- `src/lib/native-banking.ts`：以分计算的资金模型、有限指令解析、校验与事务恢复。
- `src/assets/`：从用户提供的管家概念图裁出的头像。
- `src/App.test.tsx`：主要用户流程回归测试。
- `src/App.native.test.tsx`、`src/lib/native-banking.test.ts`：双模式交互与资金逻辑测试。
